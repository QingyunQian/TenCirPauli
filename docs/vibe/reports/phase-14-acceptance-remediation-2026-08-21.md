# Phase 14 Acceptance Remediation Record, 2026-08-21

Status: remediation implementation, the complete local quality gate, and the matched post-remediation release comparison are complete; acceptance closure remains intentionally deferred only for the explicit eager-versus-lazy logical-basis A/B requested by the review.

The acceptance review's lexicographic witness defect is fixed by grouping on packed syndromes, retaining the earliest reference per syndrome, scanning the complete batch, and explicitly selecting the global minimum `(a,b)`. The regression `[III, IXI, XIX, XXX]` returns `(0,3)`, and the deterministic three-qubit matrix compares all `4**3` errors with an independent pairwise oracle.

The packed batch path now has truthful unpacked and packed result types, writes syndrome rows directly in the released Rust kernel, emits packed classification/correction arrays without a GIL-held repacking loop, and fuses correction XOR with per-row classification using call-local residual scratch. Python batch helpers now perform one final ownership conversion into read-only public arrays.

Construction limits now include original checks, statistics, elimination state, canonical construction workspace, relation storage, logical representatives, normalizer/quotient workspace, and checked syndrome-group storage for error-set analysis. QEC limits are passed through directly so deterministic small limits are meaningful; the repository-wide best-effort policy remains unchanged for other APIs.

A temporary release profile on the same machine covered repetition, finite-rate CSS, finite-rate general, and widths 64, 256, and 1024. Before the construction rewrite, finite-rate/general 1024-qubit logical pairing took approximately 0.70 seconds; after trusted reduced-basis initialization, removal of repeated pair-span rebuilding, and packed symplectic pairing it took approximately 15 milliseconds in the same profile harness. The profile was temporary and was deleted after the measurements.

The retained state now stores one rank scalar, original checks/statistics, relations, and one split packed logical representation. Canonical signed rows, provenance, stabilizer span membership, interleaved logical rows, pair spans, and ignored packed-result metadata are not retained after their current construction consumers finish. Zero-syndrome classification uses the quotient invariant that zero logical coordinates are exactly the stabilizer class.

The public result records are slotted, singular native syndrome results are flat NumPy arrays, and the example includes a non-CSS five-qubit logical-pair assertion.

The final release record `stabilizer-code-remediation-20260821-r2` completed with 144 Rust rows and 136 Python rows on the source-tree package/native extension. Against the saved pre-remediation Rust rows, repetition construction moved from 0.325 ms to 0.0325 ms at 64 qubits and from 18.895 ms to 0.6885 ms at 256 qubits; packed syndrome moved from 0.0273 ms to 0.0192 ms at 64 qubits and from 0.1337 ms to 0.1175 ms at 256 qubits. The exact old Python construction-plus-classification rows were 0.425 ms/19.687 ms at 64/256 qubits; the matched current public construction plus steady classification rows sum to approximately 0.088 ms/0.936 ms. These comparisons are workload-compatible but not claims of universal speedup.

The two complete current Python records share 94 rows; the largest r2/r1 ratio was 1.052x and the largest current Rust ratio was 1.029x. The high ratios were sub-millisecond rows or ordinary 1024-qubit variance, while the material rows were stable or faster; no row crossed the project's investigate threshold, so an additional rerun was not triggered. The failed r1 Python record is retained as an invalid measurement attempt; r2 is the successful record.

The complete repository gate then passed with cargo fmt, Clippy, 80 Rust tests, the release native rebuild, 490 Python tests, 7 doctests, Black, Ruff, strict mypy, architecture/stage checks, and `git diff --check`. Benchmark evidence remains informational and does not impose a wall-time CI gate.

The eager-versus-lazy item is not claimed as a completed A/B. The implementation deliberately keeps eager logical construction because the post-remediation profile removed the measured repeated RREF, quotient-span, and logical-pairing work while preserving one packed logical representation; a lazy alternative would require a deferred cache, synchronized first-access state, and a second runtime ownership path in an otherwise static immutable API. Introducing that machinery solely to create an unshipped comparison variant would conflict with the repository's minimality and delete-abandoned-path rules. The owner decision is therefore to keep eager, record this as an evidence limitation, and leave acceptance closure open rather than claim an A/B result that was not run.
